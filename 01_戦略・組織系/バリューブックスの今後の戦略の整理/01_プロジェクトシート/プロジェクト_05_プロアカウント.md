# プロジェクト⑤：プロアカウント・エコシステム

**担当者全員が5分で理解できるシート**

---

## 📋 プロジェクト概要

### 何を作る？（一言で）
**著者や本屋さんが自分の本を高収益で直販できるプラットフォーム**

### なぜ作る？
- **課題**: バリューブックス単体では成長に限界、パートナーと組みたい
- **解決策**: プロ向けアカウントで、みんなが儲かる仕組みを作る
- **効果**: 売上の新しい柱、エコシステム形成

---

## 🎯 目標数値（KPI）

| 項目 | 現状 | 目標（6ヶ月後） | 目標（12ヶ月後） |
|------|------|----------------|-----------------|
| パートナー数 | 0 | 3組 | 10組 |
| 月間売上 | ¥0 | ¥2,000,000 | ¥5,000,000 |
| 手数料収入 | ¥0 | ¥600,000 | ¥1,500,000 |
| パートナー継続率 | - | 100% | 90%以上 |

---

## 👥 誰が使う？（ターゲット）

- **メインユーザー**: 著者、本屋、出版社
- **利用シーン**: 書籍の直販、イベント販売、在庫処分
- **想定数**: 1年で10組、3年で30組

---

## 🔄 パートナーの流れ（簡単に）

```
【パートナー申込】
  ↓ ヒアリング・契約
【商品登録（社内で代行）】
  ↓
【Retoolダッシュボードで売上確認】
  ↓ 商品が売れる
【収益分配（70%がパートナーへ）】
  ↓ 継続して販売
【成功事例として発信】
```

---

## 💻 システム構成（ざっくり）

```
┌──────────────────────────┐
│  パートナー               │
│  ・商品情報提供           │
│  ・ダッシュボード閲覧     │
└─────────┬────────────────┘
          │ データ入力（初期は代行）
┌─────────▼────────────────┐
│  Retool（管理画面）       │
│  ・売上レポート           │
│  ・在庫管理               │
│  ・注文管理               │
└─────────┬────────────────┘
          │
┌─────────▼────────────────┐
│  バリューブックスDB       │
│  商品・注文・売上         │
└───────────────────────────┘
```

### 使う技術

| 部分 | 技術 | 理由 |
|------|------|------|
| 管理画面 | Retool | 3日で構築可能、ローコード |
| 商品登録 | 人力（初期） | システム化は後回し |
| 在庫管理 | 既存システム | 統合管理 |
| レポート | Retool → PDF | メール送付で簡単 |

## ⚠️ リスクと対策

### リスク1: パートナーが売れなくて離脱
**対策**: 
- 最初から手厚いサポート
- 一緒に売る施策を考える
- 最低保証も検討

### リスク2: 広げすぎて質が落ちる
**対策**: 
- 最初は10組まで
- 新規は慎重に選ぶ
- 「広さより深さ」を徹底

### リスク3: 法的トラブル
**対策**: 
- 弁護士監修の契約書
- 利用規約を明確に
- 問題が起きたら即対応
