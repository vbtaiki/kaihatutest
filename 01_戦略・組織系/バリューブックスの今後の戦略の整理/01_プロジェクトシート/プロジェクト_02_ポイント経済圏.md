# プロジェクト②：ポイント経済圏

**担当者全員が5分で理解できるシート**

---

## 📋 プロジェクト概要

### 何を作る？（一言で）
**売る・買う・使うが全部ポイントで繋がる、ぐるぐる循環する仕組み**

### なぜ作る？
- **課題**: 本を売った人は去っていく、買う人も1回きり
- **解決策**: ポイントで繋ぎ止めて、何度も使ってもらう
- **効果**: LTV（お客さん一人の生涯価値）が **1.5倍** に

---

## 🎯 目標数値（KPI）

| 項目 | 現状 | 目標（6ヶ月後） | 目標（12ヶ月後） |
|------|------|----------------|-----------------|
| ポイント受取率 | 0% | 10% | 20% |
| 月間ポイント発行額 | ¥0 | ¥5,000,000 | ¥10,000,000 |
| ポイント利用率 | - | 60% | 80% |
| LTV | ¥10,000 | ¥12,000 | ¥15,000 |

---

## 👥 誰が使う？（ターゲット）

- **メインユーザー**: 既存の買取・購入ユーザー全員
- **利用シーン**: 買取申込時、商品購入時、限定グッズ交換
- **想定人数**: 年間10万人 → ポイント利用者3万人

---

## 🔄 ユーザーの流れ（簡単に）

```
【本を売る】
  ↓ 現金 or ポイント選択
【ポイント受取（+10%お得！）】
  ↓ ポイント貯まる
【本・グッズを買う】
  ↓ ポイント使う
【また本を売る】
  ↓ ぐるぐる循環！
```

---

## 💻 システム構成（ざっくり）

```
┌─────────────────────────┐
│  ユーザー（Web/アプリ）  │
│  ・ポイント残高表示      │
│  ・交換・利用            │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│  ロイヤリティSaaS        │
│  ・ポイント管理          │
│  ・履歴・有効期限        │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│  既存システムと連携      │
│  ・買取・販売DB          │
└──────────────────────────┘
```

### 使う技術

| 部分 | 技術 | 理由 |
|------|------|------|
| ポイント管理 | ロイヤリティSaaS | 自社開発不要、6ヶ月→1ヶ月 |
| フロント | 既存Web/アプリに追加 | 新規開発不要 |
| API連携 | Python FastAPI | 既存システムと統合 |
| データベース | 既存PostgreSQL | 統合管理 |

## ⚠️ リスクと対策

### リスク1: ポイント発行しすぎて赤字
**対策**: 
- 月間発行上限を設定
- データを見ながら上乗せ率を調整（10% → 8%等）

### リスク2: ポイント使ってくれない（死蔵）
**対策**: 
- 有効期限を設定（1年）
- 期限が近づいたらリマインド通知
- 魅力的な交換先を用意

### リスク3: SaaSの機能制約
**対策**: 
- 導入前に要件を詳細確認
- POC（実証実験）を実施
- 複数SaaSを併用も検討
