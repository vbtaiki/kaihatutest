# プロジェクト④：SKYPOD倉庫革命

**担当者全員が5分で理解できるシート**

---

## 📋 プロジェクト概要

### 何を作る？（一言で）
**ロボットが本を運んでくる自動化倉庫で、検品作業を1/4に削減**

### なぜ作る？
- **課題**: 人手での検品・ピッキングに限界、人件費も高騰
- **解決策**: SKYPODで自動化＆協力型買取の事前データで効率化
- **効果**: 処理能力 **3倍**、人件費 **半減**

---

## 🎯 目標数値（KPI）

| 項目 | 現状 | 目標（1年後） |
|------|------|--------------|
| 検品作業比率 | 100% | 25%（75%削減） |
| 1日の処理能力 | 3,000冊 | 10,000冊 |
| ピッキング速度 | 100冊/時 | 300冊/時 |
| 人件費（月） | ¥3,000,000 | ¥1,500,000 |

---

## 👥 誰が使う？（ターゲット）

- **メインユーザー**: 倉庫スタッフ（15名 → 8名に削減可能）
- **利用シーン**: 毎日の入庫・出庫作業
- **効果を受ける**: 全ユーザー（発送が早くなる）

---

## 🔄 作業の流れ（変化）

### 従来
```
本が到着
  ↓ 人が歩いて棚まで移動
全部の本を開封・検品
  ↓ 時間かかる...
手作業でピッキング
  ↓ 疲れる...
梱包・発送
```

### SKYPOD導入後
```
本が到着
  ↓ リスクスコアで自動判定
【低リスク】→ そのままGO（検品省略）
【高リスク】→ 簡易検品のみ
  ↓ 検品75%削減！
ロボットが本棚ごと運んでくる
  ↓ もう歩かない！
梱包・発送
```

---

## 💻 システム構成（ざっくり）

```
┌──────────────────────────┐
│  協力型買取からの事前データ │
│  ・本の状態                │
│  ・ユーザー信頼度          │
└─────────┬────────────────┘
          │
┌─────────▼────────────────┐
│  中間アプリ（Go言語）       │
│  ・リスクスコア計算        │
│  ・SKYPODへ指示            │
└─────────┬────────────────┘
          │
┌─────────▼────────────────┐
│  SKYPOD制御システム        │
│  ・ロボット制御            │
│  ・在庫管理                │
└────────────────────────────┘
```

### 使う技術

| 部分 | 技術 | 理由 |
|------|------|------|
| 中間アプリ | Go | 高速、並行処理強い |
| SKYPOD | ベンダー提供 | 実績あり、保守付き |
| リスクスコア | Python | データ分析に強い |
| 既存WMS連携 | API | 最小限の改修 |

## ⚠️ リスクと対策

### リスク1: ロボットの故障・停止
**対策**: 
- 24時間保守契約
- 手作業へのフォールバック手順整備
- 予備機の確保

### リスク2: 中間アプリのバグ
**対策**: 
- エースチームによる慎重な開発
- 徹底的なテスト
- 本番投入後1ヶ月は常駐体制

### リスク3: スタッフの不安（仕事奪われる？）
**対策**: 
- 丁寧な説明会（雇用は守る）
- 新しい業務へのトレーニング
- 判断業務にシフト（やりがいUP）
