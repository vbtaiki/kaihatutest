# バリューブックス 開発原則（シンプル版）

**誰でも分かる、システム開発の基本ルール**

---

## 🎯 3つの基本方針

### 1️⃣ 作らないで済むなら作らない（Buy > Build）

```
❌ 自社開発（6ヶ月）
   ↓
⭕ SaaS利用（1ヶ月）
```

**例：**
- ポイント管理 → 専門SaaSを使う
- EC機能 → Shopifyを使う
- 管理画面 → Retoolで作る

**メリット：**
- 開発期間が**80%短縮**
- バグが少ない（実績あるシステム）
- 保守が楽

---

### 2️⃣ 小さく始めて、段階的に（MVP思考）

```
Phase 1（3ヶ月）: 最小限の機能
    ↓ フィードバック
Phase 2（3ヶ月）: 改善版
    ↓ さらに改善
Phase 3（6ヶ月〜）: 本格版
```

**メリット：**
- 早く市場に出せる
- ユーザーの声を聞きながら改善
- 失敗しても被害が小さい

---

### 3️⃣ データで判断する

```
感覚 ❌ → データ ⭕
```

**必ずやること：**
- A/Bテスト
- ログ記録
- ダッシュボードで可視化

---

## 💻 使う技術（標準）

### アプリ・画面

| 何を作る | 使う技術 | 理由 |
|---------|---------|------|

| 何を作る | 使う技術 | 理由 |

| 🚀 API（高速） | Go | めちゃくちゃ速い |
| 💾 データベース | PostgreSQL | 安定、実績多い |

## ✅ 品質管理

### テストは必須

```
┌─────────────────┐
│  手動テスト     │  人が実際に操作
├─────────────────┤
│  自動テスト     │  ロボットが自動チェック
└─────────────────┘

目標：自動テスト80%
```

---

### デプロイ（リリース）の流れ

```
開発環境（自由にテスト）
    ↓
テスト環境（本番と同じ環境）
    ↓ OKなら
本番環境（お客さんが使う）
```

---

## 🔒 セキュリティ

### 守るべき3つ

1. **パスワード**
   - 暗号化して保存
   - 絶対に平文保存しない

2. **個人情報**
   - 必要最小限だけ集める
   - アクセスログを記録

3. **APIキー（秘密の鍵）**
   - 環境変数で管理
   - Gitにアップロード禁止

---

## 📝 ドキュメント（最小限）

### 絶対に必要な5つ

1. **README** - プロジェクト説明、使い方
2. **API仕様書** - エンドポイント一覧
3. **ER図** - データベース構造
4. **システム図** - 全体の繋がり
5. **運用手順書** - デプロイ、障害対応

## 🚀 開発の心得

### 迷ったら思い出す3つ

1. ✅ **シンプルに**
   - 複雑にしない
   - 誰でも分かるコード

2. ✅ **ユーザー第一**
   - 速さ、使いやすさ
   - バグを最小限に

3. ✅ **チームで作る**
   - コードレビュー必須
   - 困ったら相談
