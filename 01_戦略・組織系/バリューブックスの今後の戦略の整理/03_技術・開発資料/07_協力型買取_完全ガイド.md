#### ① 価格決定アルゴリズムの革新
```
従来：今の相場のみ考慮
→ 一律20〜30%の買取率

当社：予測販売価格 × 時間 × 確率

```

**具体例：**
- すぐ売れる人気本：定価の60%で買取（従来の2倍）
- 時間がかかる本：定価の20%で買取（従来と同じ）

```
【ステップ1】 本棚をスマホで撮影（30秒）
      ↓

      ↓
【ステップ5】 予測より良ければボーナス還元
```

**所要時間：**従来30分 → **5分**（6分の1）

```
ユーザーが事前に状態入力

    ↓
処理能力3倍、コスト半減
    ↓
浮いたコストを買取価格に還元
```

**Win-Win:**
- ユーザー：高く売れる
- 当社：効率化でコスト削減

## 💡 価格の革新性

### 従来の買取価格決定

```
今の相場だけを見る

例：今500円で売れてる → 200円で買取（40%）
```

**問題：**
- 将来の価値を考慮していない
- すぐ売れる本も、時間がかかる本も同じ掛け率

---

### バリューブックスの価格決定

```
予測販売価格 × 売れるまでの時間 × 確率
を考慮して、「今」の買取価格を決定
```

#### 計算ロジック（概念図）

```
買取価格 = 予測販売価格 × 時間係数 × 確率 × 利益率

【時間係数】
- 即売れ（1週間以内）: 0.9
- 短期（1ヶ月以内）: 0.8
- 中期（3ヶ月以内）: 0.6
- 長期（6ヶ月以内）: 0.4
- 超長期（1年以内）: 0.2

【確率】
- 需要が高い: 0.95
- 需要が中程度: 0.8
- 需要が低い: 0.5

【利益率】
- 標準: 0.5（50%）
- 協力あり: 0.7（70%）
```

---

### 具体例

#### パターンA：すぐ売れる人気本
```
予測販売価格: 1,000円
売れるまでの予測: 1週間
確率: 95%
協力あり（状態登録）

買取価格 = 1,000円 × 0.9 × 0.95 × 0.7
         = 598円

👉 約600円で買取（60%）
```

#### パターンB：時間がかかる専門書
```
予測販売価格: 1,000円
売れるまでの予測: 6ヶ月
確率: 80%
協力あり

買取価格 = 1,000円 × 0.4 × 0.8 × 0.7
         = 224円

👉 約200円で買取（20%）
```


- スマホアプリで実装可能

### ② 書籍同定AI（実現可能：★★★★☆）

#### 役割
- OCR結果 + 画像情報から書籍を特定
- 確信度が低い場合は「Unknown」判定

#### ロジック

```python
# 疑似コード
def identify_book(ocr_text, image_vector):
    # Step 1: OCR結果でDB検索
    candidates_from_text = search_by_text(ocr_text)
    
    # Step 2: 画像ベクトルでDB検索
    candidates_from_image = search_by_vector(image_vector)
    
    # Step 3: スコアリング
    scores = calculate_similarity(
        candidates_from_text,
        candidates_from_image
    )
    
    # Step 4: 閾値判定
    if max(scores) > THRESHOLD:
        return book_id
    else:
        return "Unknown"  # 無理に判定しない
```

#### Unknown設計（重要）

**Open-set判定**
- DBに無い本は100%「分からない」
- 誤同定をしない設計
- ユーザーに手動入力を促す

**メリット：**
- 信頼性が高い
- 誤った価格提示を防ぐ

#### 類似技術の実績
- **Amazon**: 商品画像認識
- **Google Photos**: 自動分類
- **Shazam**: 音楽認識（同じ原理）

#### 技術的難易度：**中**
- OCR精度は90%程度
- 画像認識で補完すれば95%以上
- Unknown判定で安全性確保

#### データソース

| データ | 内容 | 用途 |
|--------|------|------|
| 過去販売価格 | 実際に売れた価格 | 基準価格 |
| 販売日数 | 出品〜販売までの日数 | 時間係数 |
| 季節性 | 月ごとの需要変動 | 補正値 |
| 在庫量 | 現在の在庫数 | 希少性判定 |
| 類似書籍 | ジャンル・著者等 | クラスタ分析 |
| トレンド | Google Trends等 | 需要予測 |

#### モデル構成

##### Phase 1: ルールベース + 簡易回帰
```
予測価格 = 過去平均価格 × 季節補正 × 在庫補正

予測期間 = 過去平均日数 × 在庫補正
```

**メリット：**
- シンプルで説明可能
- すぐに実装できる
- 精度は60〜70%でOK

##### Phase 2: 機械学習モデル
```
使用アルゴリズム:
- LightGBM（決定木系）
- XGBoost
- ニューラルネット

特徴量:
- 書籍メタデータ（著者、ジャンル、出版年）
- 過去販売履歴
- 外部トレンドデータ
- 季節・曜日
```

**メリット：**
- 精度向上（80%以上）
- 複雑なパターンも学習

##### Phase 3: 深層学習
```
Transformer系モデル
- 書籍の文脈理解
- 時系列予測
```

#### 重要な考え方

**完璧な予測は不要**

```
目的: 100%当てること ❌
目的: 説明可能で納得感のある予測 ⭕
```

**なぜなら：**
- 予測より良ければボーナスで還元
- 予測より悪くても、買取価格は保証済み
- ユーザーは「だいたい合ってる」で満足

#### 法務・会計上の扱い

**重要：委託販売ではない**

| 項目 | 協力型買取 | 委託販売 |
|------|-----------|----------|
| 所有権 | 買取時点でバリブに移転 | ユーザーのまま |
| 価格決定 | 買取時に確定 | 売れた時点で確定 |
| 在庫リスク | バリブが負う | ユーザーが負う |
| ボーナス | 好意的な利益分配 | 売上からの手数料控除 |

**会計処理：**
- 買取時：仕入（費用）
- ボーナス：販売促進費（費用）

→ **通常の買取業務＋ポイント付与**と同じ扱い

#### リスクスコア管理

```
【到着時の判定】

ユーザー信頼度（申告精度）
  ×
本の状態リスク（過去データ）
  =
リスクスコア

┌──────────────────────┐
│ リスクスコア < 30    │ → そのままGOレーン
│ リスクスコア 30-70   │ → 簡易検品
│ リスクスコア > 70    │ → しっかり検品
└──────────────────────┘
```

---

#### ユーザー信頼度の計算

```python
def calculate_user_trust_score(user_id):
    past_records = get_user_buyback_history(user_id)
    
    accurate_count = 0
    total_count = len(past_records)
    
    for record in past_records:
        if record.declared_condition == record.actual_condition:
            accurate_count += 1
    
    trust_score = (accurate_count / total_count) * 100
    
    return trust_score

# 例
# 過去10回の買取で、9回正確 → 信頼度90点
```
