# バリューブックス プロアカウント 完全構想

**本の流通を再発明するプラットフォーム戦略**

> 単なるアフィリエイトを超え、「バリューブックスをみんな（ステークホルダー）の会社にする」ための重要なエンジン

---

## 📌 エグゼクティブサマリー

### プロアカウントとは

Amazonや楽天などの巨大プラットフォームへの依存度を下げ、**自社サイトでの直接販売**を強化することで利益構造を改革し、その利益をパートナー（著者・書店・版元）へ還元する仕組み。

### 3つのコア機能

| 機能 | 対象 | 一言で言うと |
|------|------|------------|
| **サプライヤー機能** | 出版社・著者 | 本を預けて、より多くの人に届ける |
| **プロモーター機能** | インフルエンサー・著者 | 本を紹介して、対価を得る |
| **バイヤー機能** | 書店・小売店 | 卸価格で仕入れて、自店で売る |

### なぜやるのか

1. **脱プラットフォーム依存**: Amazon等の手数料や広告費を削減
2. **商流のデザイン**: 著者や版元、書店が参加できる新しい本の循環システム
3. **ステークホルダーオーナーシップ**: 貢献者に株式を付与し「自分ごと」化

## 🏗️ 3つのコア機能 詳細

---

### 1. サプライヤー機能（Vendor Portal）

**「本を持っていて、より多くの人に売りたい」を実現**

出版社や著者がバリューブックスに商品を登録して納品する機能。従来の取次ルートを通さず、バリューブックスの倉庫を物流拠点として直販する。

#### 対象ユーザー
- 出版社（大手〜小規模）
- 自費出版の著者
- ZINE・私家版の制作者

#### 提供機能

| 機能 | 詳細 | 優先度 |
|------|------|--------|
| **商品登録システム** | ISBN有無問わず登録可能（ZINE、私家版対応） | ★★★ |
| **価格設定機能** | 販売価格（定価）と卸価格（納入価格）を設定 | ★★★ |
| **納品管理** | 納品申請→着荷→在庫確認のダッシュボード | ★★★ |
| **在庫リアルタイム確認** | 倉庫の在庫状況をいつでも確認 | ★★☆ |
| **自動精算システム** | 売れた分の代金を毎月自動集計・支払い | ★★★ |
| **販売データ分析** | 「誰が（どのプロモーター経由で）売ったか」可視化 | ★★☆ |

#### ユーザージャーニー

```
【出版社・著者】商品情報登録
       ↓
   価格設定（定価・卸価格）
       ↓
   納品申請 → 倉庫へ発送
       ↓
   在庫反映・販売開始
       ↓
   売上レポート確認
       ↓
   毎月自動精算・入金
```

#### 検討事項
- [ ] 最低ロット数は設けるか？
- [ ] 倉庫保管料の設定（無料 or 一定期間後有料）
- [ ] 返送・廃棄ルールの策定
- [ ] ISBN無し商品の検索性向上策

### 2. プロモーター機能（Creator Portal）

**「本を紹介して稼ぐ」を実現**

バリューブックスに登録されている本を紹介し、サイトを通じて販売、フィーを得る機能。

#### 対象ユーザー
- 著者（自著を紹介）
- インフルエンサー・YouTuber・Podcaster
- 書評家・ブロガー
- 書店（セレクト本棚として）

#### 提供機能

| 機能 | 詳細 | 優先度 |
|------|------|--------|
| **キュレーションページ作成** | 自分の「おすすめ本棚」「特集ページ」をVB内に作成 | ★★★ |
| **紹介リンク発行** | トラッキング付きリンクでの成果計測 | ★★★ |
| **成果報酬管理** | 紹介経由売上レポート・フィー管理 | ★★★ |
| **在庫リクエスト機能** | 「この本を紹介したいから仕入れて」リクエスト | ★★★ |
| **報酬受取オプション** | 現金 / ポイント / 株式（将来） | ★★☆ |

#### 💡 最重要機能：在庫リクエスト（Demand-Driven Stock）

**従来のアフィリエイトとの最大の違い**

```
【プロモーター】「次回のラジオでこの本を100冊売りたい」
       ↓ リクエスト送信
【バリューブックス】出版社と交渉・在庫確保
       ↓
【プロモーター】放送日に合わせて在庫が揃っている状態
       ↓
   番組で紹介 → 販売 → 成果報酬
```

これができると、従来の書店と違う「**攻め**」のプロモーションが可能に。

#### 収益モデル

| 売上経由 | プロモーターへの還元 | 備考 |
|----------|---------------------|------|
| 自著販売 | 約70% | サプライヤー機能と連動 |
| 他著紹介販売 | **約20%** | 成果報酬として |

#### 検討事項
- [ ] 在庫リクエストの承認フローと対応SLA
- [ ] プロモーターのランク制度（実績による優遇）
- [ ] 株式付与の具体的スキーム
- [ ] グッズ・イベントチケット・有料コンテンツへの拡張

### 3. バイヤー機能（Wholesale Portal）

**「バリューブックスの在庫を仕入れて自店で売る」を実現**

バリューブックスを「巨大な卸倉庫」として開放し、書店が割引価格で購入できる機能。

#### 対象ユーザー
- 独立系書店
- セレクトショップ
- 古書店
- イベント主催者

#### 提供機能

| 機能 | 詳細 | 優先度 |
|------|------|--------|
| **卸売マーケットプレイス** | ログインで全在庫が卸価格表示 | ★★★ |
| **複合発注機能** | 中古・新刊・プロアカウント本を一括カート | ★★★ |
| **品質フィルタリング** | 品質ランク（非常に良い、可など）で絞り込み | ★★☆ |
| **まとめ配送** | 週次・月次でまとめて配送オプション | ★★☆ |
| **請求書払い対応** | 法人向け後払い対応 | ★★☆ |

#### 卸売の対象商品

| 商品タイプ | 説明 |
|------------|------|
| 中古本 | バリューブックスの既存在庫 |
| プロアカウント本 | サプライヤー機能で登録された直販本 |
| 新刊（取次仕入） | バリューブックスが取次から仕入れた新刊 |

→ すべてを混ぜて1回の発注で仕入れられることが**最大の価値**

#### 卸価格の考え方

```
例：定価 ¥2,000 の本

・バイヤー仕入れ価格：¥1,600（20%OFF）
・バイヤー販売価格：¥2,000（定価）
・バイヤー粗利：¥400

※中古本の場合は品質に応じてさらに低価格設定
```

#### 検討事項
- [ ] 最低発注金額の設定
- [ ] 送料体系（一定金額以上で送料無料など）
- [ ] 返品ポリシー（新刊 vs 中古）
- [ ] 与信審査の基準

## 🗺️ 実現ロードマップ

---

### フェーズ1：実証と定着（Initial Stage）

**ゴール**: 身近なパートナーが日々の業務をこのシステムで完結できる状態

#### 対象パートナー
- **自社**: 積読チャンネル、NABO、ブックギフト
- **外部**: B&B、ゆる言語学ラジオ

#### 実現する状態

| パートナー | できること |
|------------|-----------|
| 積読チャンネル | 紹介した本をプロモーターリンクで販売、成果報酬獲得 |
| NABO | 古本・新刊をバイヤー機能で仕入れ |
| B&B | バイヤー機能での仕入れ＋独自セレクトのアフィリエイト |
| ゆる言語学ラジオ | 番組紹介本の在庫リクエスト＋成果報酬 |

#### KPI
- パートナー数：3〜5組
- 月間売上：¥2,000,000
- パートナー継続率：100%

---

### フェーズ2：拡張と深化（Next Stage）

**ゴール**: 今までできなかったことが機能として実装され、新しい経済圏が生まれる状態

#### 【書店】の新しい姿（NABO、B&B）

| 従来 | フェーズ2 |
|------|----------|
| 古本仕入れのみ | **新刊20万冊**もバリューブックスから仕入れ可能 |
| 本のみ販売 | オリジナル商品をVB経由で販売・他店卸も |
| 売上のみ | アフィリエイト収入＋買取手数料など多様な収入源 |

#### 【著者・インフルエンサー】の新しい姿（積読、ゆる言語）

| 従来 | フェーズ2 |
|------|----------|
| 本を紹介して終わり | **在庫リクエスト**で放送前に出版社交渉・確保 |
| 本のアフィリエイトのみ | グッズ・イベントチケット・有料コンテンツ販売 |
| 著者としてAmazon依存 | **発売時の販売支援**＋営業・プロモーション支援 |

→ 影響力のある著者が複数参加し始める

#### 【出版社】の新しい姿（有力著者を持つ1〜2社）

| 従来 | フェーズ2 |
|------|----------|
| 書店経由のみ | 発売時のLPとして使い書店取り分を著者・版元へ |
| プロモは自社負担 | その金額で一緒にプロモーションも行える |
| 物流は取次依存 | 他書店への卸売・取次への物流もVBが担う |

#### KPI
- パートナー数：10〜20組
- 月間売上：¥10,000,000
- 新刊在庫：20万冊

---

### フェーズ3：展開と標準化（Final Stage）

**ゴール**: プロアカウントが出版業界の新しい流通インフラになる状態

#### アクション
- **パートナー開拓専門チーム**の結成
- 営業部隊による積極的な有力パートナー獲得

#### 実現する世界

```
┌─────────────────────────────────────────────────────────┐
│     プロアカウント = 出版業界のOS（基本ソフト）        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  著者 ←→ 出版社 ←→ バリューブックス ←→ 書店 ←→ 読者   │
│         ↑               ↑               ↑              │

```

- 多くの出版社・著者がAmazon・取次と同列にバリューブックスを選択肢として利用
- 「使わないと損」なレベルのサービス水準

#### KPI
- パートナー数：100組以上
- 月間売上：¥50,000,000以上
- 業界メディアでの認知・取材

## 💰 収益モデル

### バリューブックスの収益源

| 収益タイプ | 内容 | 料率目安 |
|------------|------|----------|
| 販売手数料 | サプライヤー商品の販売手数料 | 30% |
| プロモーターフィー原資 | 自社在庫販売時の販売価格から | 20% |
| 卸売マージン | 卸価格と仕入原価の差額 | 10-20% |
| 物流手数料 | 保管・発送代行 | 実費＋マージン |

### パートナーの収益

| パートナータイプ | 収益モデル |
|------------------|-----------|
| サプライヤー（出版社・著者） | 販売価格の約70%（従来の3-7倍） |
| プロモーター | 紹介売上の約20% |
| バイヤー（書店） | 卸仕入れによる粗利（20%OFF仕入れ） |

## 🔮 将来展望：ステークホルダーオーナーシップ

### 構想

プロアカウントの貢献者（パートナー）に対して、金銭報酬だけでなく**株式（ストック）**を付与。

- 会社の一部を持ってもらう
- バリューブックスの成長を「自分ごと」として捉えてもらう
- 長期的なコミットメントを引き出す

### 連動する施策

| 施策 | 連動内容 |
|------|----------|
| 新YouTubeチャンネル | 動画紹介が収益・株価に連動 |
| 本の惑星 | メディアとプロアカウントの融合 |
| IPO（24周年目標） | パートナーも株主として参加 |

### 検討事項
- [ ] ストックオプションか株式付与か
- [ ] 付与基準（売上連動？貢献度？）
- [ ] 法務・税務の整理
- [ ] 株主総会への参加権

```
├──────────────┬──────────────┬──────────────┬────────────────┤

│   ポータル   │   ポータル   │   ポータル   │ ダッシュボード │
├──────────────┴──────────────┴──────────────┴────────────────┤
│                         API層                               │
├─────────────────────────────────────────────────────────────┤
│  商品管理 │ 在庫管理 │ 注文管理 │ 精算管理 │ 分析・レポート │
├─────────────────────────────────────────────────────────────┤
│               バリューブックス既存システム                   │
│            （在庫DB・決済・物流・顧客管理）                  │

```

### 技術選定（初期）

| コンポーネント | 技術 | 理由 |
|---------------|------|------|
| 管理画面 | Retool | 3日で構築可能、ローコード |
| 商品登録 | 人力 → 段階的自動化 | MVPは手動運用 |
| 在庫管理 | 既存システム連携 | 統合管理 |
| レポート | Retool → PDF/メール | シンプル運用 |
