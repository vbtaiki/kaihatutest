## 2026/02/13

### 形式
Slackレポート（キンスウェイ → 中村、片山、CC: 落合）

### 本棚を指定しない検索の実験結果

**実施内容**: 本棚を指定せず全体のDBから検索した場合の精度を検証

#### ①ルールベース判定の結果

| 判定結果 | 本棚指定あり | 本棚指定なし |
|---------|------------|------------|
| 採用・正解 | 1,525件（75.09%） | 655件（32.25%） |
| 採用・不正解 | 4件（0.20%） | 3件（0.15%） |
| 不採用（AI判定対象） | 498件（24.52%） | 1,369件（67.41%） |
| 対象外（OCR文字なし） | 4件（0.20%） | 4件（0.20%） |

**落合コメント**:
- 本棚指定ありで不正解だった4件は、全て在庫に正解がない本だった
- 指定なし検索の不正解3件は別の理由:
  - 2件: 背表紙画像が大きく欠けている
  - 1件: PHP研究所の雑誌「PHPスペシャル」（OpenSearch上にない可能性）
    - https://www.php.co.jp/magazine/phpsp/?unique_issue_id=05365

**発見事項**: 採用・正解の655件のうち、25件は在庫データに存在しない本を正解として判定していた

#### ③Gemini AI判定（全2,031件を一括判定）の結果

ルールベースチェックを行わず、全2,031件を背表紙画像＋候補情報でGemini AI（Gemini 3 Flash Preview）に判定させた結果。

| 判定結果 | 本棚指定あり | 本棚指定なし |
|---------|------------|------------|
| 不採用 | 172件（8.47%） | 254件（12.51%） |
| 採用・正解 | 1,854件（91.29%） | 1,694件（83.41%） |
| 採用・不正解 | 5件（0.25%） | 83件（4.09%） |

**まとめ**: 採用率は91.54%→87.50%に低下、不正解率は0.25%→4.09%に上昇

### 検証の手順（キンスウェイ提案・実施済み）

```
① OpenSearchで本棚指定なし検索 → 候補情報をJSON出力
  → ルールベースチェック時に抽出済みのものを使用
② 背表紙画像からGemini 3 Flash Previewで情報をJSON抽出
  → 前回Geminiで抽出済みの結果を使用
③ 背表紙画像＋候補情報をGemini AIに渡して判定
  → ①と②の結果を組み合わせて判定
```

### 片山さんリクエスト
- 前回までの結果と今回の結果を数字を並べて比較できるようにする → 対応済み

### ③ 棚指定なし検索の精度

- ルールベースでは3割程度が採用、不正解は3件
- 不採用分に対するOpenAI判定、背表紙画像を渡したGemini判定の不正解率が高い

**改善アクション:**
- ルールベースの採用基準を調整（スコア差の閾値のチューニング）
- GeminiのAI判定のプロンプトを調整

### ■ 本棚スキャンの精度改善に向けた検討 — 背表紙画像の活用方針

背表紙画像については以下の3パターンの利用が考えられる：

| パターン | 内容 | 方針 |
|---------|------|------|
| 1. OCR結果を保存 | LINE OCRの結果をそのまま保存 | ✅ **採用**（本棚スキャン時と同じOCRを使うことが重要） |
| 2. 特徴量を抽出して保存 | EfficientNetなどで抽出 | 🔄 候補あり（OCR結果と組み合わせると有効） |
| 3. ベクトル化して保存 | 画像をベクトル化 | 🔄 候補あり |

**特徴量の活用イメージ:**
- ルールベースで採用したが、背表紙の**色合いが違う**ので不採用にする
- ルールベースでは似ている本があって区別できないが、**色合いから採用するものを決められる**

→ 特徴量はそれだけで判断するのではなく、**OCR結果と組み合わせる**ことで効果を発揮する

### ■ 次週までの対応

背表紙の画像データを使う部分**以外**の精度改善を先に実施：
- ルールベースの採用基準を調整（スコア差の閾値のチューニング）
- GeminiのAI判定のプロンプトを調整
