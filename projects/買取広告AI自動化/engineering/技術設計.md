# 技術設計

> 買取広告AI自動化システムの技術設計・アーキテクチャ

---

## アーキテクチャ概要

```
Phase 1（現在）: 静的HTML+JS プロトタイプ
  app/index.html + app.js → ブラウザで完結。モックデータで全画面体験可能。

Phase 2（次フェーズ）: バックエンド + API連携
  フロントエンド（React or Vue）
    ↕ REST API / GraphQL
  バックエンド（Node.js or Python FastAPI）
    ↕ 媒体API（Google Ads / Meta Ads / LINE Ads）
    ↕ 画像生成AI（DALL-E / Stable Diffusion）
    ↕ データ分析ストア（BigQuery）

Phase 3（高度化）:
  デザインシステム準拠チェック
  自動A/Bテスト判定
  チラシ印刷入稿対応
```

---

## Phase 1 実装（プロトタイプ）

### ファイル構成

| ファイル | 役割 |
|---------|------|
| `app/index.html` | 6タブSPA。全UIコンポーネントを含む |
| `app/style.css` | デザインシステム（CSS変数・コンポーネントクラス） |
| `app/app.js` | モックデータ定義・全UI描画ロジック・インタラクション |

### 実装済み画面

1. **ダッシュボード**: KPI4つ、媒体別パフォーマンス表、7日間推移チャート（純粋CSS/JS）、TOP3クリエイティブ
2. **予算配分プラン**: 目標入力フォーム、媒体別スライダー、AIレコメンド計算（モック）、配分計画表
3. **クリエイティブ分析**: 12件のモックデータ、媒体・訴求軸・ソートフィルター、グリッド表示
4. **クリエイティブ自動生成**: 訴求軸チップ選択、ターゲット選択、媒体選択、2.2秒後に生成アニメーション＋結果表示
5. **人間 vs AI コンペ**: 3件のサンプルコンペペア、CTR/CVR/CPAスコアバー比較、勝者表示、人間案追加モーダル
6. **入稿キュー**: 10件のキューアイテム、承認/差戻/入稿操作、一括承認・自動入稿ボタン

## Phase 2 技術スタック（検討中）

| レイヤー | 候補技術 | 備考 |
|---------|---------|------|
| フロントエンド | React + TypeScript | または Vue 3。既存プロジェクトとの統一を要検討 |
| バックエンド | Python FastAPI | AI/MLライブラリの豊富さから。Node.jsも可 |
| データベース | PostgreSQL | キャンペーン・クリエイティブの管理 |
| 分析ストア | BigQuery | 広告パフォーマンスデータの蓄積・分析 |
| AI推論 | OpenAI GPT-4o | コピー生成・分析レコメンド |
| 画像生成 | DALL-E 3 / Stable Diffusion | バナー画像の自動生成 |
| タスクキュー | Celery + Redis | 非同期入稿処理 |
| インフラ | GCP or AWS | バリューブックスの既存環境に合わせる |

## 媒体API連携（Phase 2）

### Google Ads

- 使用API: Google Ads API（v17以降）
- 認証: OAuth2.0 サービスアカウント
- 主要エンドポイント: `CampaignService`, `AdGroupService`, `AdService`
- 入稿フロー: クリエイティブデータ → `ResponsiveDisplayAd` or `ResponsiveSearchAd` 作成

### Meta Ads

- 使用API: Marketing API（v20.0以降）
- 認証: アプリアクセストークン
- 主要エンドポイント: `/act_{ad_account_id}/ads`
- 入稿フロー: Image Upload → AdCreative 作成 → Ad 作成

### LINE Ads

- 使用API: LINE Ads API
- 入稿フロー: 管理画面CSV入稿または直接API（要調査）

## セキュリティ考慮事項

- 媒体APIキーは環境変数で管理（絶対にコードに埋め込まない）
- 入稿前の人間承認ステップは初期フェーズで必須
- 広告費の上限設定による誤入稿防止機能を実装必須
