# 技術設計

> ポイント経済圏の技術仕様・アーキテクチャ

---

## アーキテクチャ概要

```
[Webフロントエンド] ←→ [API Gateway] ←→ [ポイントサービス]
                                            ├── ポイント付与API
                                            ├── ポイント利用API
                                            ├── 残高照会API
                                            └── 有効期限管理
                                                   ↓
                                            [ポイントDB]
                                                   ↓
                                            [通知サービス]
```

---

## 技術スタック

| カテゴリ | 技術 | 理由 |
|---------|------|------|
| フロントエンド | React + Next.js | 既存システムとの統合 |
| バックエンド | Node.js / Express | チーム技術スタック |
| データベース | PostgreSQL | トランザクション管理の信頼性 |
| キャッシュ | Redis | ポイント残高の高速参照 |
| 通知 | SendGrid + LINE API | メール・LINE連携 |

---

## データベース設計（概要）

### ポイント残高テーブル
```
point_balances:
  - user_id (FK)
  - total_balance (int)
  - available_balance (int)
  - updated_at (timestamp)
```

### ポイント取引テーブル
```
point_transactions:
  - id (PK)
  - user_id (FK)
  - type (earn/use/expire)
  - amount (int)
  - source (buyback/campaign/etc)
  - expires_at (timestamp)
  - created_at (timestamp)
```

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| パフォーマンス | ポイント残高照会は100ms以内 |
| セキュリティ | ポイント操作は認証必須、不正利用検知 |
| スケーラビリティ | 月間100万トランザクションに対応 |
| 可用性 | 99.9%以上 |

---

## 技術的なリスク

- 既存の決済システムとの統合の複雑さ
- ポイント計算の精度（丸め処理）
- 大量のポイント期限切れ処理のバッチ負荷
