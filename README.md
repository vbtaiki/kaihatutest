# バリューブックス プロジェクト協働リポジトリ

> ビジネスサイドとエンジニアが、コードを中心に協働するためのリポジトリ

---

## このリポジトリの目的

**ビジネスサイド（経営・企画）** と **エンジニア** が、以下の流れでプロジェクトを進めます：

```
エンジニア                          ビジネスサイド
  │                                     │
  ├── app/ にコードを開発               │
  ├── demo/ にデモページを更新          │
  ├── engineering/ に進捗報告        　  │
  │        ↓                            │
  │    ┌──────────┐                     │
  │    │  GitHub  │ ← 共有リポジトリ    │
  │    └──────────┘                     │
  │        ↓                            │
  │                    demo/ をブラウザで確認 ──┤
  │                    business/ にフィードバック ──┤
  │                    コード改善案をCursorで作成 ──┤
  │                            ↓
  │                    Cursor AI がGitHub送信を代行
  │        ↓
  ├── フィードバック・改善案を確認
  ├── app/ に反映
  └── 繰り返し
```

---

## 使い方

### ビジネスサイドの方

**Cursorを開いて、AIに話しかけるだけです。**

| やりたいこと | AIに言うこと |
|------------|------------|
| 最新を確認したい | 「最新の状態に更新して」 |
| デモを見たい | 「デモを確認したい」 |
| フィードバックを送りたい | 「フィードバックを書きたい」 |
| コードの改善案を作りたい | 「この色を変えた改善案を作って」 |
| エンジニアに送りたい | 「GitHubに送って」 |

📖 詳細ガイド → [`_github_workflow/01_ビジネスサイド向けガイド.md`](_github_workflow/01_ビジネスサイド向けガイド.md)

### エンジニアの方

通常のGitHub開発フローで進めます。ビジネスサイドの更新は `business/` フォルダを確認してください。

📖 詳細ガイド → [`_github_workflow/02_エンジニア向けガイド.md`](_github_workflow/02_エンジニア向けガイド.md)

## セットアップ

### 初回（エンジニアが実施）

```bash
# 1. リポジトリをクローン
git clone git@github.com:[org]/[repo].git
cd [repo]

# 2. ビジネスサイドのPCにも同様にクローン
# 3. Cursorで開く → .cursorrules が自動読み込みされる
```

### 新しいプロジェクトを追加する時

Cursorに「新しいプロジェクトを作りたい。名前は○○」と話しかけてください。
テンプレートから自動的にフォルダ構成が作られます。
