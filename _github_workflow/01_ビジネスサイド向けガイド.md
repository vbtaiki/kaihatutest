# ビジネスサイド向け Cursor 操作ガイド

> Gitもコマンドも覚えなくてOK。Cursorを開いてAIに話しかけるだけ。

---

## はじめに

このガイドは、エンジニアとGitHubを使ってプロジェクトを進めるための手順をまとめたものです。

**あなたが覚えることは3つだけ：**

1. **Cursorを開く**
2. **AIに話しかける**（Cmd+L または右のチャットパネル）
3. **日本語で伝える**

それだけです。Gitのことは一切知らなくて大丈夫です。

---

## 毎日のルーティン

### ① Cursorを開く

デスクトップのCursorアイコンをダブルクリック。
前回開いていたフォルダがそのまま表示されます。

### ② 最新の状態にする

AIチャットに以下のように入力：

```
最新の状態に更新して
```

これだけで、エンジニアが更新した内容がすべて反映されます。

### ③ デモダッシュボードを確認する

```
デモを確認したい
```

AIがデモ確認ページの場所を教えてくれます。**`demo/index.html`** をブラウザで開くと：

| タブ | 見れるもの |
|------|-----------|
| 💻 エンジニア最新版 | 動くプレビュー + 開発進捗 + エンジニアの報告 |
| 💡 ビジネス改善提案 | 自分が出したフィードバックとAI改善案の一覧 |
| 🔄 使い方ガイド | Cursorでの操作フレーズ集 |

**「📋 過去のやり取り履歴」** をクリックすると、全やり取りの一覧も見れます。

### ④ 更新内容をAIに聞く

```
今日の更新を教えて
```
```
○○プロジェクトの進捗を見せて
```
```
エンジニアから質問きてる？
```

AIが変更点を日本語で分かりやすく教えてくれます。

### ⑤ レスポンスを返す

```
○○プロジェクトにフィードバックを書きたい。
Aの方向で進めてほしい。理由は〜〜だから。
```

AIが適切なファイルに、適切なフォーマットで記録してくれます。

### ⑥ エンジニアに送る

```
これをGitHubに送って
```

以上！これだけで、エンジニアがGitHub上であなたのフィードバックを確認できます。

## よく使うフレーズ集

### 📥 情報を受け取る

| やりたいこと | AIに言うこと |
|------------|------------|
| 最新の状態にしたい | 「最新に更新して」 |
| デモを見たい | 「デモを確認したい」 |
| 特定プロジェクトの進捗を見たい | 「○○の進捗を教えて」 |
| エンジニアからの質問を確認したい | 「エンジニアからの質問を見せて」 |
| 最近の変更一覧を見たい | 「最近の更新をまとめて」 |
| コードの内容を知りたい | 「このコードは何をしてるの？」 |

### 📤 情報を送る

| やりたいこと | AIに言うこと |
|------------|------------|
| フィードバックを書きたい | 「○○にフィードバックを書きたい」 |
| 方針を記録したい | 「○○の方針を記録して：〜〜」 |
| 会議の決定事項を記録したい | 「今日の会議で○○に決まった。記録して」 |
| 新しい要件を追加したい | 「○○プロジェクトに要件を追加して：〜〜」 |
| エンジニアに送りたい | 「GitHubに送って」 |

### 💻 コード改善案を作る

| やりたいこと | AIに言うこと |
|------------|------------|
| 見た目を変えた提案を作りたい | 「この色を変えた改善案を作って」 |
| 文言を変更した版を作りたい | 「この文言を変更した版を作って」 |
| Before/Afterで比較したい | 「Before/Afterで比較できるようにして」 |
| 改善案をエンジニアに送りたい | 「これをエンジニアに送って」 |

### 🆕 新しく作る

| やりたいこと | AIに言うこと |
|------------|------------|
| 新プロジェクトを作りたい | 「新しいプロジェクトを作りたい。名前は○○」 |
| 議事録を残したい | 「○○の議事録を作って」 |

## 画面の見方

### サイドバー（左側）

```
📁 projects/
  📁 ポイント経済圏/
    📁 app/               ← エンジニアが作るコード（見るだけ）
    📁 demo/              ← 🖥️ ブラウザで開くダッシュボード
      📄 index.html       ← メインダッシュボード
      📄 history.html     ← やり取り履歴
    📁 business/          ← あなたが主に使うフォルダ
      📄 要件・方針.md
      📄 フィードバック.md
      📄 意思決定ログ.md
      📁 コード改善案/     ← AIと作った改善コード
    📁 engineering/        ← エンジニアが書くフォルダ（読むだけ）
      📄 技術設計.md
      📄 進捗報告.md       ← 進捗はここを見る
      📄 質問・相談.md     ← 質問はここに来る
    📁 shared/             ← 共有フォルダ
      📁 議事録/
```

- **`demo/`** = ブラウザで開く。プレビューや改善提案が全部見れる。
- **`business/`** = あなたの領域。ここに書く。
- **`business/コード改善案/`** = AIと一緒に作った改善コードが入る。
- **`engineering/`** = エンジニアの領域。ここを読む。
- **`shared/`** = みんなの共有スペース。

### AIチャット（右側 or Cmd+L）

ここに日本語で話しかけます。何でも聞いてOK。

## よくある質問

### Q. 間違えてファイルを消してしまったら？

A. 大丈夫です。GitHubに過去の状態がすべて保存されています。
AIに「○○のファイルを元に戻して」と言ってください。

### Q. 「コンフリクト」とか「エラー」が出たら？

A. AIに「何かエラーが出てるみたいなんだけど直して」と言ってください。
AIが対処します。それでも解決しない場合はエンジニアに連絡。

### Q. エンジニアの技術的なファイルを編集していい？

A. `engineering/` フォルダは読むだけにしてください。
フィードバックや要望は `business/フィードバック.md` に書きます。

### Q. 同時に複数人が編集したらどうなる？

A. 別の場所（ファイル）を編集していれば問題ありません。
同じファイルの同じ場所を同時に編集した場合は、AIが調整を手伝います。

### Q. オフラインでも使える？

A. ファイルの閲覧・編集はオフラインでもできます。
ただし「GitHubに送って」「最新に更新して」はインターネット接続が必要です。

### Q. Cursorを閉じても大丈夫？

A. はい。次に開いた時にそのまま続きから作業できます。
ただし「最新に更新して」を最初に言うことをおすすめします。

## トラブル時の連絡先

| 状況 | 対応 |
|------|------|
| AIで解決する問題 | Cursorに「助けて」と聞く |
| AIでも解決しない | Slackの #dev チャンネルでエンジニアに連絡 |
| 緊急の方針変更 | 直接エンジニアリーダーに連絡 |

## まとめ：1日の流れ

```
朝:
  Cursorを開く
  → 「最新に更新して」
  → 「何か更新あった？」
  → demo/index.html をブラウザで開いてプレビュー確認

日中:
  → フィードバックが必要なら「○○にフィードバック書きたい」
  → コードの見た目を変えたいなら「この色を変えた改善案を作って」
  → 方針決定があれば「これを記録して」
  → 書いたら「GitHubに送って」

退勤前:
  → 書き忘れがなければOK。Cursorを閉じる。
```

**これだけで、エンジニアとGitHubでつながった協働が実現します！**
